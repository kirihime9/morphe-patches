# AGENTS.md

Morphe patch bundle (Android bytecode patchers written in Kotlin), not an app. The deliverable is `patches/build/libs/patches-<version>.mpp`, consumed by Morphe Manager/Desktop.

## Layout

- `patches/` — Kotlin/JVM module; all patches live under `app.morphe.patches.<app>.<feature>/`.
- `extensions/extension/` — Android/Java extension code compiled to `extensions/extension.mpe` and embedded into the `.mpp`. The template leftover (`app.template.extension`) is live, not dead code.
- Modules are auto-included by the `app.morphe.patches` plugin in `settings.gradle.kts` (no `include(...)` lines). Don't add manual includes or apply plugins to modules.
- Patches are discovered by scanning the built jar (`loadPatchesFromJar`). A top-level `val fooPatch = patch(...) { }` is enough; there is no registry file to update.

## Commands

- `./gradlew :patches:compileKotlin` — fastest feedback after editing patch code.
- `./gradlew :patches:buildAndroid` — real build: DEX + extensions + optional signature into `patches/build/libs/patches-<version>.mpp`. Plain `build`/`jar` produces a bundle without `classes.dex`.
- `./gradlew :patches:generatePatchesList` — runs `util.PatchListGeneratorKt`, regenerates root `patches-list.json`.
- `./gradlew :patches:generateSigningKey` — creates `morphe-signing.pub` + `morphe-signing.key`; refuses if either already exists.
- No tests exist. Verify by compiling, then applying patches to a real APK with Morphe Desktop.
- JDK 21 in CI; Kotlin/Java target JVM 11; Gradle 9.8.2 wrapper.
- Dependency resolution needs GitHub Packages auth: `GITHUB_ACTOR`/`GITHUB_TOKEN` env or `gpr.user`/`gpr.key` Gradle properties (registry is `MorpheApp/registry`). Builds fail without it.

## Release pipeline — never hand-roll

- Push to `dev` auto-opens a PR to `main` (`open_pull_request.yml`); `release.yml` runs semantic-release on every push. `dev` = prerelease, `main` = stable. Merge dev → main, do not squash.
- Conventional commits drive versions: `feat:` minor, `fix:`/`perf:` patch, `bump:` patch + "Updated App Support" notes, `chore:` no release.
- `patches-list.json`, `patches-bundle.json`, `CHANGELOG.md`, and the README block between `PATCHES_START`/`PATCHES_END` are generated by CI. Do not edit or hand-commit them.
- Never force-push semantic-release commits.
- Signing: `morphe-signing.pub` is committed; the private key comes from `MORPHE_SIGNING_KEY` or a local `morphe-signing.key` (gitignored). A key that doesn't match the committed `.pub` fails `buildAndroid`. Never commit the `.key`.

## Patch authoring gotchas

- `p0` is not always 4-bit encodable. In a 31-register method `p0` maps to `v29`, so `iput-boolean ..., p0` fails in the inline compiler. Use `method.getFreeRegisterProvider(0, 2, method.p0Register)` plus `getFreeRegister4Bit()`, and `move-object/from16` to copy `p0`.
- morphe-patcher 2.5.0 made `Patch` non-generic: use `Set<Patch>`, not `Set<Patch<*>>`.
- Per-app metadata belongs in `shared/compat/AppCompatibilities.kt`; patches call `compatibleWith(AppCompatibilities.X)`.
- Keep the version-catalog aliases named `morphe-patcher` and `smali`; the Gradle plugin resolves them by name and adds the dependencies itself. Bumping `morphe-patcher` can break patch APIs.
- Everything under `patches/src/main/kotlin` ships inside the `.mpp` (including the `util` generator classes), so don't put build-only tooling there.

## Conventions

- Version lives in `gradle.properties` (`version = 1.0.0`); semantic-release bumps it.
- One package per app: `app.morphe.patches.<app>.<feature>` with a sibling `Fingerprints.kt`.
- `*.apk` is gitignored, so test APKs can sit in the repo.
